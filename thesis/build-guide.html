Thesis PDF build

Edit the .tex files and build the PDF by hand on Ubuntu. The build commands on this page were run on your laptop on 20 Nov 2026. The footer lists what was not tested.

On this laptop TeX is already installed, so you do not need Docker to build the PDF. Docker gives a PDF with the same page count, with nothing installed except Docker.

1. One-time setup

Ubuntu 24.04. All of these are already installed on your laptop (checked 20 Nov). On a new machine:

sudo apt install make latexmk python3 fontconfig \
  texlive-xetex texlive-latex-base texlive-latex-recommended texlive-latex-extra \
  texlive-pictures texlive-plain-generic texlive-publishers texlive-lang-greek \
  texlive-fonts-recommended fonts-cmu fonts-lmodern fonts-texgyre-math fonts-liberation

2. Build the PDF

cd ~/consensus-bench-framework/thesis
make

Output: thesis-en.pdf (38 pages) and thesis-el.pdf (39 pages), in thesis/. Git ignores both.

CommandWhat it does
make thesis-en.pdfEnglish only. make thesis-el.pdf for Greek only.
make checkRuns every check and prints a report. Always exits 0.
make check-strictFewer checks (sync, parity, diagrams, measurements, citations), and it stops at the first failure. Run it before you submit.
make syncLists the Greek blocks that are behind the English.
make dataLists the measurements still marked [PENDING].
make cleanDeletes the build files and both PDFs. Use it when a build acts strangely, then run make.

After an error, make ends with Errors, so I did not complete making targets, but it can still write a PDF. Find the error with grep -n -A1 '^!' thesis-en.log: the l.120 line gives the line number.

3. Edit with live preview in VS Code

Do steps 1–3 once.

  1. Install the extension: 
    code --install-extension James-Yu.latex-workshop
  2. Tell it to use XeLaTeX. Its default recipe uses pdflatex, which cannot build this thesis. This creates thesis/.vscode/settings.json, which git already ignores. If the file already exists, it stops and you add the lines by hand: 
    mkdir -p ~/consensus-bench-framework/thesis/.vscode
f=~/consensus-bench-framework/thesis/.vscode/settings.json
[ -e "$f" ] && echo "$f exists: add the lines by hand" || cat > "$f" <<'EOF'
{
  "latex-workshop.latex.recipe.default": "latexmk (xelatex)",
  "latex-workshop.latex.autoBuild.run": "onSave",
  "latex-workshop.latex.search.rootFiles.include": ["**/main-en.tex", "**/main-el.tex"]
}
EOF
  3. The preview is named main-en.pdf (or main-el.pdf), not thesis-en.pdf. Hide it from git status on this machine only: 
    echo 'thesis/main-*.pdf' >> ~/consensus-bench-framework/.git/info/exclude

Then, every time:

  1. Open the thesis folder, not the whole repo: code ~/consensus-bench-framework/thesis
  2. The first time only: open main-en.tex and press Ctrl+Alt+B, then do the same with main-el.tex. After that, each chapter builds its own edition.
  3. Open a chapter, for example content/en/ch1.tex.
  4. Ctrl+Alt+B builds. Ctrl+Alt+V opens the PDF in a tab on the right.
  5. Save with Ctrl+S. The PDF rebuilds and refreshes, in about 5 seconds after a small edit.
  6. Ctrl+click in the PDF jumps to that line of the source. Ctrl+Alt+J jumps from the source to the PDF.
  7. Errors appear in the Problems panel (Ctrl+Shift+M), with the file and the line.
  8. The PDF tab name, main-en.pdf or main-el.pdf, shows which edition you are looking at. Ctrl+Alt+C deletes the preview's build files.
  9. For the final PDFs, run make in the VS Code terminal (Ctrl+`).

Do not set an output folder (outDir). The chapters are included with \include, and TeX then cannot write their .aux files into subfolders that do not exist, so the build stops.

4. Terminal + Evince (any editor)

One terminal watches the sources and rebuilds when you save any file:

cd ~/consensus-bench-framework/thesis
latexmk -xelatex -pvc -view=none -interaction=nonstopmode -file-line-error -jobname=thesis-en main-en.tex

Open the PDF next to your editor. Evince reloads it after each rebuild:

evince ~/consensus-bench-framework/thesis/thesis-en.pdf &

Ctrl+C stops the watcher. For Greek, use -jobname=thesis-el main-el.tex.

5. Docker (optional)

The image is Ubuntu 24.04 with the packages from step 1: about 820 MB, built in about 2 minutes. Its recipe is thesis/docker/Dockerfile, new on 20 Nov; commit it so a new clone has it. Build the image once:

cd ~/consensus-bench-framework
docker build -t thesis-tex thesis/docker

Then build from the thesis folder. Your files are mounted, not copied, and the PDFs belong to you, not to root:

cd ~/consensus-bench-framework/thesis
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD:/thesis" thesis-tex make
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD:/thesis" thesis-tex make check

Docker does not cover make docx, which also needs pandoc, python-docx, docxcompose and LibreOffice.

6. Switch to the department's Word look

In style/common.tex, line 22, change \latexlooktrue to \latexlookfalse, then run make. It uses Times New Roman when it is installed (it is on your laptop), otherwise Liberation Serif, which has the same widths. Either way the English PDF has 37 pages and the Greek 38. Change it back for the LaTeX look.

7. Rules the build enforces

  • Edit the English first (content/en/), then the Greek. After you translate a block, run python3 tools/sync.py --stamp --id BLOCKID.
  • New text: start each English paragraph with %%blk chapter.topic.01. Above its Greek translation, write %%blk chapter.topic.01 from=PLACEHOLDER, then stamp it. python3 tools/sync.py --new lists the blocks not translated yet.
  • New chapter: content/en/chN.tex and content/el/chN.tex, with an \include line at the same place in main-en.tex and main-el.tex. make check compares the two page orders.
  • A number from your own measurements goes into data/measurements.tex and is used as \meas{key}. It prints [PENDING] until you fill it in.
  • Do not commit PDFs or .docx files. They are build outputs.

8. When something goes wrong

You seeDo this
VS Code: fontspec package requires either XeTeX or LuaTeXThe pdflatex recipe ran. Check the settings file from section 3, step 2, and open the thesis folder, not the repo.
I can't write on file `frontmatter/en/cover.aux'An output folder is set. Remove it (see the note in section 3).
pzdr ... not loadableInstall texlive-fonts-recommended.
Log: CMU fonts not found, so the Word look is usedInstall fonts-cmu.
Odd results after many editsmake clean, then make.

9. Other editors

EditorFits this repo?
VS Code + LaTeX WorkshopYes. Live preview beside the source, jumps both ways, and a terminal for make. Free, and already installed.
TeXstudioYes, if you prefer a LaTeX-only app: sudo apt install texstudio. Set XeLaTeX as the compiler, BibTeX for the bibliography, and main-en.tex (or main-el.tex) as the root document. It has its own PDF viewer. Not tested here.
OverleafOnly to view or share. The PDF builds there (Menu → Compiler → XeLaTeX, as main-en.tex says), but make, the checks and the Greek sync do not run. Git sync needs a paid plan (from memory, not checked).

Tested on 20 Nov 2026 on Ubuntu 24.04.5 (TeX Live 2023, latexmk 4.83), on clean copies of commit 121cf05 plus the new Dockerfile, then rerun by an independent reviewer:

  • make builds both PDFs.
  • The Docker image passes 25 test assertions: fonts embedded, no missing characters, no undefined references, files owned by you, and the Word look.
  • latexmk -pvc rebuilds after an edit.
  • The exact command of LaTeX Workshop's "latexmk (xelatex)" recipe builds main-en.pdf with SyncTeX.
  • The settings above are valid for LaTeX Workshop 10.20.0.
