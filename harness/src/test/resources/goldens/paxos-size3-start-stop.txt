# size-3 start + stop (paxi framework), verbatim, in order, host:port$ cmd.
# Human read-through checklist (what differs from etcd, and why it's right):
#  * config.json carries REAL private IPs in BOTH maps — address (tcp,
#    inter-node :1735) and http_address (client REST :8080); IDs are
#    single-zone "1.1".."1.3" (source-verified paxi shape). It is written
#    to the node with a single-quoted printf (the JSON's own quotes are
#    double, so single-quoting is safe and the file is human-reviewable —
#    no base64 to hide behind).
#  * --network host + a bind mount of that file to /config.json (paxi reads
#    config.json from cwd=/, no WORKDIR in the image); the image is the
#    SOURCE-pinned tag paxi:6823d0b (no registry digest exists — D2-adapted).
#  * -adaptive is paxi's DEFAULT and stays on (F26 decision): a hard
#    leader_kill wedges rather than fails over — the honest "no failure
#    detector" result.
#  * readiness is a COMMITTED PROBE WRITE, not a port/health check: paxi
#    elects its first leader LAZILY on the first request and exposes no
#    /health. The probe PUTs key 1 to node1 over the private net and is
#    retried by the provider until it returns 200.
#  * deterministic thesis-paxi<i> names; pre-clean SWEEPS every thesis-*
#    container on EVERY provisioned node (F29 — stale cross-system or
#    size-down leftovers, same rationale as the etcd golden); teardown
#    removes every container this cluster started.
#  * IMAGE-PRESENCE GATE (F33): paxi:6823d0b exists in NO registry — a
#    bare docker run on a fresh VM would try to pull and fail at first
#    contact. The inspect per member node fails closed with the shipping
#    command (docker save | ssh docker load) in the message.
